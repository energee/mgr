## Decisions
- This issue ID has a three-act history in the repo: PR #297 (`a9c0803`,
  2026-07-05) fixed a prefill-store `sessionStorage` read happening during
  render instead of in `useEffect`; PR #306 (`ea2d3dc`, 2026-07-05) fixed
  unpinned `toLocaleDateString()`/`toLocaleString()` calls causing
  locale-dependent SSR/CSR text mismatches. Despite both, the issue kept
  recurring — last seen `2026-07-11T02:25:44.917Z`, release
  `00fbe7913c326d42cf160a59673e5b79bff32c90`.
- The sibling Sentry issue MGR-6 (`SENTRY-7477285440`) — identical culprit
  URL, identical release, identical last-seen minute — was investigated in a
  prior session and root-caused to `TrendChartLazy`/`BatchActivityHeatmapLazy`
  (`src/components/dashboard/`) using `next/dynamic({ ssr: false })` nested
  inside `ProductionTrends`' own genuinely-suspending `<Suspense>`
  (`usePeriod()` → `useSearchParams()`) — a documented Next.js hydration
  hazard, same class of bug already fixed for `ChatLayout` in PR #308. That
  was fixed by PR #396 (`5a7d9cc`, merged 2026-07-13 12:43, i.e. after this
  issue's last event but before this session started).
- Given the matching release/culprit/timestamp, and that React can emit
  multiple distinct hydration-mismatch events from a single page load (each
  grouped by Sentry under a different component-stack fingerprint), concluded
  these are twin events from the same incident. Verified the current
  `src/app/(app)/dashboard/page.tsx` and `dashboard/sales/page.tsx` already
  use the `React.lazy` + explicit-`Suspense` fix from PR #396 at all 4 call
  sites — no remaining `/dashboard`-specific code change was needed for this
  recurrence. This mirrors the exact precedent already recorded for
  `SENTRY-7477285440` in `docs/feature_list.json` (evidence `pr:396`).
- Pattern-scanned for the same defect class as this issue's *own* history
  (browser-storage read during render instead of in an effect — exactly
  PR #297's mechanism) across the rest of the codebase. Found
  `usePersistedPageSize` (`src/hooks/use-persisted-page-size.ts:31`) reading
  `localStorage` inside a `useState(() => ...)` lazy initializer. It backs
  `EntityDataTable` (`src/components/universal/entity-data-table.tsx:52`),
  used by every entity list page — a real, still-live hydration bug whenever
  a user has a non-default persisted page size (server renders the default,
  client's first render reads the stored value). Not on `/dashboard`, but the
  identical defect class this issue's own history has twice required fixing,
  so included it in scope per the pipeline's pattern-scan step.
- Fixed by deferring the `localStorage` read to `useEffect` (state starts at
  `defaultSize`, effect corrects it once after mount), mirroring the
  established `usePrefillHydration` pattern exactly (same file family already
  fixed this exact mechanism for this same issue ID).
