## Decisions
- 2026-07-13T05:05Z — Traced the log message to `ProductionTrends`'s `useQuery` `queryFn` (dashboard/page.tsx:409), which caught the `get_production_trends` RPC error and `return []`-ed instead of throwing. — This makes React Query treat the failed fetch as a *successful* empty result: `isError` never becomes true, so the UI silently renders zeroed-out stat cards with no error indication. The Sentry event itself is just the (correctly-forwarded, since `PostgrestError extends Error` — verified in `node_modules/@supabase/postgrest-js/src/PostgrestError.ts`) `log.error` call; the real defect is the swallow-and-return-`[]` pattern, not a client-logger gap.
- 2026-07-13T05:10Z — Pattern scan (Grep for `log.error(.*error)` + manual read) found the identical bug duplicated in `InventoryTrends` (`dashboard/inventory/page.tsx:316`) and `SalesTrends` (`dashboard/sales/page.tsx:441`). — Included all three in the fix scope per the pipeline's pattern-scan step.
- 2026-07-13T05:15Z — Fix: `throw error` after the existing `log.error` call in all three `queryFn`s; destructure `isError`; render `<DashboardEmpty message="Couldn't load … trends" icon={AlertTriangle} />` on error. — Matches the `isError` idiom already established elsewhere in this codebase (`reports/ttb/page.tsx`, `order-pick-list.tsx`, `fg-inventory-section.tsx`); `DashboardEmpty` was already imported in all three files, so no new component needed.
- 2026-07-13T05:20Z — Exported `ProductionTrends` (previously module-private) so it could be rendered directly in a Vitest regression test without mounting the entire dashboard page tree. — The repo has no `@testing-library/react`; tests render real components via `createRoot` (`src/test/react-harness.ts`), so the target component must be importable.
- 2026-07-13T05:35Z — Independent review agent flagged: `isError` alone would blank an already-successfully-loaded chart on any transient background-refetch failure, since these queries poll every 60s (`refetchInterval: 60000`) and TanStack Query sets `status: 'error'` unconditionally on a failed fetch attempt (verified in `node_modules/@tanstack/query-core/src/query.ts` reducer — the `data` field is preserved across a background error, but `status` flips to `'error'` regardless). Narrowed the condition to `isError && trends.length === 0` in all three files so a transient poll failure keeps showing the last known-good data instead of flipping to an error placeholder; only a failure with no data at all (e.g., initial load) surfaces the error state. — Avoids trading the original silent-failure bug for a new "flashes to error on every network blip" regression.
