## Plan

Fix Sentry issue MGR-8 where `NotificationsProvider` crashes with "No QueryClient set" because it calls `useQueryClient()` unconditionally at render time. The error was captured from the `polish` git worktree at `GET /`. The fix is a minimal guard component that checks `QueryClientContext` via `useContext` (which never throws) and serves a no-op fallback context instead of crashing when no `QueryClientProvider` is present.

## Decisions

- 2026-05-14T22:35:00Z — Used `QueryClientContext` (exported public API from `@tanstack/react-query` v5) rather than an error boundary class component. Reason: avoids class component, works cleanly with hooks rules, and `QueryClientContext` is stable across the entire v5 lifecycle.
- 2026-05-14T22:40:00Z — Split into outer guard (`NotificationsProvider`) + inner implementation (`NotificationsProviderInner`) rather than wrapping the whole thing in a try-catch. Reason: hooks can't be called inside try-catch; the split keeps each component's hook call count stable across renders.
- 2026-05-14T22:45:00Z — Added `log.error` production warning in the fallback path. Reason: code review identified that a silent fallback in production would swallow provider ordering regressions; the original error was loud and caught quickly, so observability should be restored.
- 2026-05-14T22:50:00Z — Used `Boolean(useContext(QueryClientContext))` rather than `!== null`. Reason: `QueryClientContext` defaults to `undefined` (not `null`), so strict null-check would always evaluate to `true`.
