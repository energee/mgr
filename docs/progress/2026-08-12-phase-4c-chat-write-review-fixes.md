- **2026-08-12 (Phase 4C chat-write: unit-blind validation + timestamp trust fixes).** Follow-up to #745's review: `validateReading` (`src/domain/batch-readings.ts`) now accepts an optional `unit` and converts to the canonical unit (Plato, °F) before range-checking, fixing a bug where `18 C` was refused and `60 C` (140°F) passed; both `recordBatchReading` and `POST /api/chat/write` now pass the unit through. `batchReadingSchema` (`src/lib/schemas/chat-write.ts`) — the actual trust boundary — now cross-checks `unit` against `READING_TYPES[type].units` via `superRefine` and format-validates `timestamp`; the write route re-stamps `timestamp` at execution time instead of trusting the value frozen when the tool proposed the write, so a card confirmed hours later can't backdate the reading. Added regression tests for the Celsius conversion and unit-mismatch cases in both the tool and route test suites.
