- **2026-07-29 (No web egress from credentialed generative CI jobs, #645).** `sentry-harness.yml`'s fix-error job granted `WebFetch` in `--allowed-tools` while holding `contents`/`pull-requests`/`issues: write`, a checkout that persists `GITHUB_TOKEN`, and a prompt that embeds raw Sentry event text (explicitly marked UNTRUSTED in `prompt.ts`) — the one generative job in the repo with an outbound network path for an injected instruction, since bug-patrol, feedback-distill, quality-regrade, and health-audit all pass `--disallowedTools "WebFetch,WebSearch"`; dropped the grant, denied both tools explicitly, and rewrote the "occasional docs lookup" justification comment. Audited the other five `claude-code-action` workflows and found a second outlier, `claude.yml`, which passed no `claude_args` at all (so egress was merely undeclared) while running with the same write scopes over unvetted fork-PR and issue text — it now denies the same two tools. Replaced the missing invariant with a cross-cutting contract in `.github/scripts/ci-workflows.test.ts`: per *job*, any workflow invoking `claude-code-action` with a `write` permission (or declaring none, so it inherits default token scopes) must pass `--disallowedTools` covering `WebFetch` and `WebSearch` at least once per agent step and must not name either in an allow-list — verified red against each pre-fix workflow separately and against a re-added `WebFetch` grant, so future workflows are covered without editing the test. Rule and rationale recorded in `docs/agents/ci.md`.
