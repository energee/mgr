- **2026-07-15 (SENTRY-7597067722 — Failed to fetch notifications; branch `sentry-fix/SENTRY-7597067722`).** Second recurrence of this Sentry issue (MGR-J), different root cause than the first. This event showed a browser-level `TypeError: Failed to fetch` while `NotificationsProviderInner` queried Supabase from `/sales/customers/:id` in development. Classified **(D) observability gap**: postgrest-js's fetch `.catch()` handler (confirmed by reading `PostgrestBuilder.ts` in `node_modules/@supabase/postgrest-js`) wraps network-level fetch failures — and, per its own source, some Postgrest error responses — as a plain object literal `{ message, details, hint, code }` that is *not* `instanceof Error`, despite its declared `PostgrestError` TypeScript type extending `Error`. `src/lib/client-logger.ts`'s `forward()` only routed to `Sentry.captureException` when `arg instanceof Error`, so this object silently degraded to a stack-less `Sentry.captureMessage`, matching the event exactly (title = the literal log message, stack trace unavailable). Fixed by adding a structural `isPostgrestErrorLike` check to `client-logger.ts` that constructs a real `Error` (message + stack sourced from `details`) and forwards `code`/`hint`/`details` as Sentry extra context — this fixes every `log.error`/`log.warn` call site in the app, not just notifications, since the gap was centralized. Confirmed via `src/components/dashboard/batch-activity-heatmap.tsx`'s existing `SENTRY-7597067759` comment that call sites already pass the raw error object correctly — the bug was always in the central logger's type check, not the call sites. Regression tests added to `src/lib/__tests__/client-logger.test.ts` covering (a) a network-fetch-failure-shaped object, (b) a real Postgrest DB error with a `code`, and (c) confirming an unrelated plain object still falls back to `captureMessage`; all three confirmed to fail pre-fix and pass post-fix. This does **not** resolve the underlying error — the network fetch to Supabase still fails for an unknown reason (dev-environment connectivity, DNS, or similar); that is tracked separately in a GitHub investigation issue since it isn't diagnosable or fixable from application code. `bun run typecheck`, full `bun run test` (2475 tests), and `bun lint` all clean.
