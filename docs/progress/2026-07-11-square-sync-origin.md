- **2026-07-11 (Square combined sync — no Host-derived self-fetch; branch `fix/square-sync-origin`, audit SEC-1 / backlog P2 #20).** `/api/square/sync` (POST) previously fetched `${new URL(request.url).origin}/api/square/sync/{catalog,inventory}` with the caller's cookie forwarded — `request.url` derives from the incoming Host header, so on a deployment that doesn't strictly validate Host a spoofed header could send the admin's session cookie to an attacker-chosen origin. Now the route imports the sibling route handlers and invokes them DIRECTLY as functions with the same request (chosen over the `SITE_URL` fallback: it removes the attacker-influenceable origin AND the loopback HTTP hop entirely; each inner handler still runs its own `withPermission` gate). Response shape, error semantics (CATALOG_SYNC_FAILED passthrough status, partial-success on inventory failure), and sync-log writes unchanged — the inner handlers are untouched. Same-pattern grep across `src/app/api`: the only other `request.url`-origin uses are the QuickBooks OAuth redirect-URI fallbacks (`auth/route.ts:29`, `callback/route.ts:60`) — browser-redirect URIs bounded by Intuit's registered-URI matching (SEC-1's own assessment), not self-fetch targets; left as-is. New `combined-sync-route.test.ts` (4 tests) asserts direct invocation with the identical request object and ZERO outbound fetch even under a hostile Host.
