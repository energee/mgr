- **2026-08-13 (Phase 4B — generic chat writes).** The AI chat can now persist four things instead of one, all through the 4C confirmation gate: `createBatch`, `transitionBatch`, `createPackagingSession` and the existing `recordBatchReading` each return a `ConfirmWriteIntent` the user must confirm before anything is written. `chat-write.ts` grew from one write to a four-member discriminated union — deliberately not a generic `{table, payload}` passthrough, since the union is the trust boundary — and the route moved from a blanket `withPermission("batches:write")` to `withAuth` + a per-action `requirePermission`, so a future write against another domain cannot inherit batch rights. Transitions run through `entityService.transition` (the atomic RPC that owns side effects), never a bare status UPDATE, and the route re-checks eligibility itself because a batch can move between propose and confirm. Caught late: the union and the route switch already carried `transition_batch` and `create_packaging_session` cases while both tools still returned `{action: "navigate"}`, so two of the four writes were unreachable server code — converted, then covered by tests. The navigational `addBatchReading` was deleted in favour of `recordBatchReading`: two tools for one intent made the model choose between recording the number the user just stated and opening a form they could already reach, and it chose wrong.
