- **2026-08-12 (required status checks: db-lint always-reporting shim).** Made `Database Lint and Integration Tests` eligible as a required status check on `main` (#713). The `paths:` filter moved off `on:` — where a filtered-out PR is never queued and the required context stays pending forever — and into a `changes` job that diffs the PR against `env.SCHEMA_PATHS` and fails open. The heavy `supabase-reset` / `db-lint` jobs are gated on its output; a new `db-lint-gate` job carries the required name, runs `if: always()`, and translates the heavy lane's `result` into its own exit code, exiting 1 on failure, cancellation, an unexpected skip **and** an unexpected run — the only two passing shapes are "ran and succeeded" and "correctly skipped". Recommended required set: `Static Checks`, `Unit Tests`, `E2E Tests`, `Database Lint and Integration Tests`; `Production Build` must never be added (nightly-gated) and `shell-lint.yml` stays path-filtered and advisory. `docs/agents/ci.md` gains a Required status checks section; `.github/scripts/ci-workflows.test.ts` pins the invariant (mutation-checked: 9 targeted mutations each red it). Review caught a severe bug in the first cut: `on: paths:` globs and git pathspecs are different dialects, and `supabase/migrations/**/*.sql` as a pathspec matches only *nested* `.sql` files — so it matched none of this repo's flat migrations, and every migration PR would have skipped the heavy lane and reported the required check **green**. Fixed to `supabase/migrations/*.sql`, and the contract test now *runs* `git ls-files -- $SCHEMA_PATHS` against the real tree (asserting every migration is selected and ordinary files are not) instead of pinning the patterns' spelling, which is structurally incapable of catching a pattern that reads correctly and matches nothing. Also documented two harness footguns in `docs/agents/gotchas.md` — #786 (the pre-PR gate is a `PreToolUse` hook, so `touch … && gh pr create …` can never pass; its git-dir resolution is per-worktree and **correct**, contrary to the issue text; its matcher has no shell-quoting awareness) and #785 (`/code-review` and `/simplify` have no repo-side definition at all, so nothing here can scope them to a worktree — not repo-fixable).
