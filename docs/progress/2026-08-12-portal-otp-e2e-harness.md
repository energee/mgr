- **2026-08-12 (Portal OTP E2E harness).** Authenticated customer-portal E2E is now possible: `e2e/portal-auth.setup.ts` seeds a portal customer + auth user, drives the real `/portal/login` OTP flow, reads the code out of the local Mailpit (`e2e/mailpit.ts`, plain `fetch`, no new dependency) and saves `e2e/.auth/portal.json` for a new `chromium-portal` Playwright project. `e2e/portal-orders.spec.ts` is the proof it works (passes locally against the local stack). Two local-config gaps were fixed on the way: `supabase/config.toml` had no `[auth]` section, so the local stack emitted 6-digit codes inside Supabase's stock magic-link template — which contains no code at all — meaning no OTP login of any kind was drivable locally; it now sets `otp_length = 8` (matching `OTP_LENGTH`) and points the magic-link template at `supabase/templates/magic-link.html`. Portal order *placement* stays skipped in `customer-order.spec.ts`: that blocker is the missing product UI, not the harness (#706).
