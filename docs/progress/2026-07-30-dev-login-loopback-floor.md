- **2026-07-30 (dev-login's `E2E_DEV_LOGIN` path now requires a loopback database — issue #656, branch `fix/656-dev-login-loopback-floor`).** `/api/auth/dev-login` mints a full admin session with no caller credentials, and its only negative floor was `VERCEL_ENV` — which is absent entirely off Vercel (self-hosted Docker, Fly, Railway) and can be absent on Vercel when "Automatically expose System Environment Variables" is off, making the floor a silent no-op there. Not a live bypass today (the positive conditions still fail in production: `next build`/`next start` force `NODE_ENV=production`, and `E2E_DEV_LOGIN` is set on the e2e job alone, pinned by a contract test) — the real exposure was operator error, i.e. setting `E2E_DEV_LOGIN=1` on a non-Vercel production host, where nothing was left to stop it reaching a hosted Supabase project holding real data. Fixed by binding the flag to the only situation it exists for: `E2E_DEV_LOGIN === "1"` now *also* requires `NEXT_PUBLIC_SUPABASE_URL` to have a loopback hostname (`localhost`, `127.0.0.1`, `[::1]`/`::1`), compared after `new URL()` parsing rather than by substring, so `https://localhost.evil.example.com` and `https://localhost@evil.example.com` read as remote; missing/unparseable fails closed. `host.docker.internal` deliberately excluded — no reference to it in `test.yml` or `playwright.config.ts`, so nothing needs it. The `NODE_ENV === "development"` path is untouched and still works against a hosted project, which is a normal local workflow. The Vercel production/preview floor stays.
