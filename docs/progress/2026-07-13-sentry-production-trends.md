- **2026-07-13 (Sentry MGR-K — dashboard trend queries swallowed RPC errors as empty data — branch `sentry-fix/SENTRY-7597067731`).** `ProductionTrends` (`src/app/(app)/dashboard/page.tsx`), `InventoryTrends` (`src/app/(app)/dashboard/inventory/page.tsx`), and `SalesTrends` (`src/app/(app)/dashboard/sales/page.tsx`) each caught their `get_*_trends` RPC error, logged it via `log.error`, and `return []`-ed from the `queryFn` — React Query then settled the query as a *success* with empty data, so `isError` never surfaced and the dashboard silently rendered zeroed-out stat cards/charts with no indication the fetch had failed (only a Sentry log line nobody watching the page would see). Pattern scan found the identical bug duplicated across all three trend queries; all three fixed the same way: `throw error` after the existing `log.error` call (matches the `isError`-surfacing idiom already used at `reports/ttb/page.tsx`, `order-pick-list.tsx`, `fg-inventory-section.tsx`), and an early return rendering `<DashboardEmpty message="Couldn't load … trends" icon={AlertTriangle} />` — but only when there's no cached data to fall back on (`isError && trends.length === 0`), since these queries poll every 60s and a transient background refetch failure shouldn't blank out an already-rendered, working chart in favor of an error placeholder. `ProductionTrends` exported for testability. New regression test `src/app/(app)/dashboard/__tests__/production-trends.test.tsx` mocks the RPC to fail and asserts the error state renders (confirmed red against the pre-fix `return []` code, green after). `bun run typecheck`, `bun run test` (2224 tests), and `bun lint` all clean.
