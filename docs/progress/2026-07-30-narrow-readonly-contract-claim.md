- **2026-07-30 (Narrow the read-only-token contract's coverage claim).** #689's fix (#709) added `readOnlyMintContradictions` — a job whose `permissions:` block grants no repository write must bind an explicit `github_token` — and `docs/agents/ci.md` said it "generalises to workflows nobody has enumerated yet". It does not generalise that far: `declaresReadOnly()` returns false for `{kind: "inherited"}`, so a job with **no** `permissions:` block is not covered at all, which is the most common copy-paste shape and reproduces the #689 defect invisibly. Narrowed the claim, stated the gap, and recorded the standing mitigation (give every agent job an explicit `permissions:` block). Also documented two limits an adversarial review of #709 measured: `bindsOwnToken` accepts any non-empty input, so a PAT stronger than the app token passes silently and a typo'd secret name resolves to an empty string and takes the OIDC path anyway; and a PAT supplied through `env:` is invisible to both rules. Docs only — no behaviour change.
