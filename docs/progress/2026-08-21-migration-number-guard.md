- **2026-08-21 (static guard for migration number collisions; dropped the duplicate replay job).** Duplicate `NNNNN_` version prefixes have now broken migration replay on every branch three times (00260 in #545, 00297/00298 in #920) because two in-flight PRs cannot see each other's numbers and no check runs before the push. `make check-db` now fails in milliseconds on any duplicate prefix, which is where the class belongs — the failure is a filename property, not a SQL one, and `db-lint`'s `psql` loop is structurally blind to it (it never writes `supabase_migrations.schema_migrations`). With that in place the advisory `supabase-reset` job ("Fresh Supabase Migration Replay") was removed from `db-lint.yml`: it booted a third Docker Supabase per PR to replay a chain `db-lint` and `E2E Tests` already replay, and on #878 it produced nothing but a second red X for a failure `E2E Tests` had already reported. `make db-dry-run` is unchanged for local use.
