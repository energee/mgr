- **2026-07-14 (PO receiving SQL cleanup).** Follow-up to #417's `receive_purchase_order_items`. Migration `00249` replaces the `CREATE TEMP TABLE _submitted ON COMMIT DROP` with a CTE (the temp table throws "relation already exists" if the function is ever called twice inside one transaction, since `ON COMMIT DROP` does not drop until commit — safe today only because PostgREST gives each RPC its own transaction), drops a dead `li.quantity IS NULL` branch (`po_line_items.quantity` is `NOT NULL`), and gives an entry naming a line item from another order its own error instead of reporting it as "Cannot receive more than was ordered … ordered 0". The status rule, `FOR UPDATE` serialization, transition validation, and `SECURITY INVOKER` are unchanged. The transition table stays a hardcoded `CASE` rather than reading `enum_values.metadata->'next_states'`: those rows are mutable metadata with a documented drift history (00192) and no other SQL consumer, so sourcing the rule from them would trade a visible duplication for a receiving path that silently rejects every transition if a row goes missing.
