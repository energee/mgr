- **2026-07-15 (Sentry fix MGR-S — createRevisionHistoryDisplay client-boundary crash).** Fixed SENTRY-7611936148: `createRevisionHistoryDisplay()` is invoked eagerly at module scope inside every entity `presentation.tsx` (e.g. `component: createRevisionHistoryDisplay("batches")`), but its defining file (`revision-history-display.tsx`) carried an unneeded `"use client"` directive — it has no hooks of its own; the real client-only logic already lives in the child `RevisionHistory` component, which carries its own directive. When a Server Component imports the assembled entity (rather than the server-safe core), that eager call hit a Next.js client-reference proxy and threw "Attempted to call X() from the server but X is on the client." Removed the incorrect directive. Pattern scan found the identical shape in `createQBOSyncDisplay` (customer/supplier/order/purchase-order presentations) — its factory lived in the same file as the real hook-using `QBOSyncSection`, which *does* need `"use client"`. Split the factory into a new `qbo-sync-display.tsx` (no directive), mirroring the revision-history split. Confirmed today's live routes already dodge this via the `batchCore`-not-`batchEntity` convention introduced in the same sitewide-loading-pattern work (`docs/plans/2026-07-15-sitewide-loading-pattern.md`), so this hardens the underlying pattern rather than papering over a still-reachable crash. Added `src/components/domain/shared/__tests__/entity-config-client-boundary.test.ts` (source-text regression test, since Vitest doesn't enforce Next's RSC client-boundary transform) — confirmed it fails against the pre-fix files and passes after. `make check` green.
