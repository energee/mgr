- **2026-07-30 (dev-login's NODE_ENV path now checks which database it touches — issue #679, option 2).** `/api/auth/dev-login` handed out an uncredentialed **admin** session on the strength of `NODE_ENV === "development"` alone, with nothing checking the target project — so any dev server reachable over a LAN, tunnel, bound `0.0.0.0` or reverse proxy and wired to a hosted Supabase project gave that reach admin. PR #678 had hardened only the sibling `E2E_DEV_LOGIN` path and left this one as a documented, accepted exposure. #679 asked for a decision between five options and is labelled `needs-human`; **option 2 was selected during an automated backlog sweep, not by the owner** — the choice, its rationale and its reversibility are recorded in [a comment on #679](https://github.com/energee/mgr/issues/679#issuecomment-5132054772), and the owner can still override it. (An earlier draft of this note said "implemented the owner's decision". No such decision existed; that claim was false and is retracted here.) Option 2: loopback stays the silent default, and a non-loopback project now needs `DEV_LOGIN_ALLOW_REMOTE_DB=1` — reusing #678's `getSupabaseUrl()` accessor and `LOOPBACK_HOSTNAMES` rather than adding a second loopback check, with `hasLoopbackSupabaseUrl()` widened into a three-state `classifySupabaseTarget()` (`loopback` / `remote` / `unknown`) so an unresolvable URL fails closed on both paths and no opt-in overrides it. `unknown` covers three shapes, not one: absent, unparseable, and **parseable-but-hostless** (`localhost:54321`, `file:///x`, `mailto:a@b` all yield `hostname === ""` — the first cut classified those as `remote`, so the opt-in did admit a target the gate never identified). The gate and the login page's Dev Login button now read one shared module (`src/lib/dev-login.ts`) instead of two `NODE_ENV` tests that had silently diverged: the page hides the button when no opt-in could open the route, and names the required variable on screen when one could, so a refusal is explained before the click instead of arriving as raw `{"error":"Not found"}`. `.agents/skills/verify/verify.sh` and `scripts/smoke-test.sh` — the two other consumers, both missed by the first pass — now name #679 and both fixes when auth fails. The server-side warning is a second channel, not the only one, and the docs say plainly that `LOG_LEVEL` can suppress it. Suites 51 → 101 tests across the route (42 → 86) and login-form (9 → 15) files, red-checked five ways (18 / 1 / 1 failures against the pre-change gate; 9 with the empty-hostname guard removed; 4 with the button back on its own `NODE_ENV` predicate). Not taken, and now tracked rather than left as prose: option 3, bind the listening interface (#691); option 4, `DEV_LOGIN_TOKEN` (#692); option 5, narrow the `roles: ["admin"]` upsert (#683). #679 itself stays open for the owner to confirm or override — the PR says `Refs`, not `Closes`.
