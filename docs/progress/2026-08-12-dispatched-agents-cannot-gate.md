- **2026-08-12 (dispatched agents cannot run their own quality gates).** Measured across six parallel worktree nodes, then confirmed by a direct probe: a dispatched expert agent gets no `Task`, `Agent`, or `Skill`, so it cannot dispatch `refactor-reviewer` or invoke `/simplify` and `/code-review`. Every node reported this independently and four worked the reviewer checklist by hand, honestly labelling the result self-assessed rather than gated. The obvious cause — the six write agents declaring `tools: Read, Grep, Glob, Bash, Edit, Write`, which omits Task and Skill — does **not** fully fit: a probe of `entity-architect` reported its actual set as `Read, Bash, Edit, Write`, four tools, with the declared `Grep` and `Glob` absent. The declared list is not simply being honoured. Those six files now read `tools: "*"`, which is at least not misleading, but the change is **unverified** — the same probe showed it had no effect within the session that made it, consistent with agent definitions resolving at session start. The two read-only gate agents were deliberately left restricted; a gate that can edit is not a gate. The durable fix is process, not config, and is now in `docs/agents/dispatching-agents.md`: **the orchestrator runs the gates in a second pass**, and a brief must not instruct a node to run gates it cannot reach, because that invites a fabricated "gates passed". Run centrally on the 2.0 Wave 3 work, those gates caught four defects the authoring agents missed — a type narrowed from `string | null` behind an `as unknown` cast, a stale cross-reference at the exact seam an extraction argued must not drift, a docblock claiming script-portability while importing `@sentry/nextjs`, and two receipts with wrong test counts.
