A grid faithful to all 5 collapses to a near-empty Table+map+delete shell wrapping 5 large bespoke rewrites — minimal dedup, 5 high-risk migrations, zero test coverage to verify byte-faithful output. The explicit all-5-or-revert gate makes partial migration worthless.
- [ ] **B2 · `SortableRowsEditor` + reuse `CatalogPicker`** 🟡 (~700) — **BLOCKED: shell not uniform + CatalogPicker reuse not behavior-preserving.** (1) The Sortable shell diverges: grain-bill/hop/mash wrap a `<Table>`, but `fermentation-schedule-editor` wraps `<SortableContent>` directly (non-table layout), and the drag overlays differ (mash/fermentation use `SortableDragPreview`; grain-bill/hop render bespoke overlays). A `readOnly` fold would make the editor reproduce the display's distinct DOM in a separate branch — two divergent render trees in one file (more complex, not less). Decisively, there is ZERO test coverage for any of these presentational components or the recipe detail view, so `bun run test` cannot confirm a merged read-only render is DOM/behavior-identical — any subtle divergence is a silent user-visible regression.
